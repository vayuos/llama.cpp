PROBLEM IDENTIFIED & FIXED:
---------------------------
Previous Phase 3B implementation had COMPLETELY INVERTED logic:
- Old logic: Targeted layers 0-24 for CUDA_Host placement
- Root cause: Assumed early layers = CPU-resident (false in your config)
- Actual config: Layers 0-12 CPU, Layers 13-48 GPU
- Result: Moved GPU-layer KV to CPU (massive 24 t/s bottleneck)
- Regression: -24% performance (31.89 → 24 t/s)

SOLUTION IMPLEMENTED:
--------------------
Device-aware detection instead of layer-index logic:
1. Get actual device assignment via ggml_backend_dev_name(dev)
2. Check if device name contains "CPU" string
3. Only apply CUDA_Host pinned memory to CPU-resident layers
4. GPU-resident layers completely unaffected
5. No regression risk - GPU layers can't be worse
