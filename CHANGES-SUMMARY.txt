ROOT CAUSE
──────────
.cu files were not being compiled as CUDA code by nvcc.
They were instead being compiled as C++ files by g++.
Result: No device code generated → linker errors for device symbols

SOLUTION
────────
Enable CUDA language support at all CMake levels and explicitly mark
.cu files as CUDA language BEFORE creating library target.

TECHNICAL DETAILS: Why the Ordering Matters
─────────────────────────────────────────────

CMake MUST process source file properties BEFORE creating the target.

When you call set_source_files_properties() AFTER adding files to a target,
CMake ignores the properties because the target is already configured.

WRONG SEQUENCE:
  1. ggml_add_backend_library() - Target created, files associated
  2. set_source_files_properties() - Properties set, but target already done
  3. Result: Properties are ignored
  4. .cu files compiled with default (g++/C++) → linker errors

CORRECT SEQUENCE:
  1. set_source_files_properties() - Set properties first
  2. ggml_add_backend_library() - Create target with properties applied
  3. Result: Properties are used
  4. .cu files compiled with nvcc (CUDA) → device symbols generated
