WHY THIS WORKS
================================================================================

The problem: CMake cached CUDA configuration from a failed build attempt
The solution: Remove EVERYTHING and rebuild from scratch with CPU-only

By clearing all CMake cache, we prevent CMake from remembering the failed
CUDA build and trying to use the broken libggml-cuda.so.0.9.5 library.

================================================================================
IF YOU NEED CUDA ACCELERATION
================================================================================

Only do this if you have an NVIDIA GPU and CUDA toolkit installed:

1. Install CUDA Toolkit:
   sudo apt-get install cuda-toolkit

   OR download from: https://developer.nvidia.com/cuda-toolkit

2. Set environment:
   export PATH=/usr/local/cuda/bin:$PATH
   export LD_LIBRARY_PATH=/usr/local/cuda/lib64:$LD_LIBRARY_PATH

3. Verify CUDA:
   nvcc --version  # Should show CUDA version

4. Complete reset and rebuild:
   bash COMPLETE-BUILD-RESET.sh
   ./scripts/build-gpu-exclusive.sh cuda

COMMON ISSUES & FIXES
================================================================================

Q: Reset script asks for confirmation but I want to skip it
A: The script intentionally requires confirmation to prevent accidents

Q: After reset, build still fails with same errors
A: This shouldn't happen. Try:
   - Make sure you ran: bash COMPLETE-BUILD-RESET.sh
   - Check: ls build_cuda/ (should be empty or not exist)
   - Check: ls -la CMakeCache.txt (should not exist)

Q: Want to see what gets deleted before confirming
A: Script shows all files/dirs to be deleted before asking for confirmation

Q: Build seems slow after reset
A: Normal - fresh build compiles everything. Use: -j16 for faster build
   ./scripts/build-gpu-exclusive.sh cpu -j16

Q: How do I know which build type to use?
A: - CPU: Always works, good for testing
   - CUDA: 10-100x faster, requires NVIDIA GPU + CUDA toolkit

================================================================================
TECHNICAL EXPLANATION
================================================================================

What happened:
1. Previous build enabled CUDA (-DGGML_CUDA=ON)
2. CUDA toolkit not installed, build partially failed
3. Created broken libggml-cuda.so.0.9.5
4. CMake cached CUDA configuration
5. All tools tried to link against broken library
6. Result: Linker errors for every tool

Why COMPLETE-BUILD-RESET.sh fixes it:
1. Removes all build directories
2. Deletes CMakeCache.txt (where CMake caches decisions)
3. Deletes CMakeFiles/ (cached build configuration)
4. Forces fresh CMake configuration on next build
5. New configuration detects no CUDA toolkit
6. CMake configures for CPU-only build
7. Build succeeds without CUDA
